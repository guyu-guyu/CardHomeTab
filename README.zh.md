# CardHomeTab

**中文** · [English](README.md)

把一篇 Markdown 笔记变成启动页。CardHomeTab 按标题切分这篇笔记，用 Obsidian 自己的渲染器把每个 section 渲染成一张卡片，并允许每张卡片引用自己的 CSS。

## 功能

- 首页视图：logo（内置图标、仓库图片或网络图片）、文字标识、背景图（亮/暗两套，支持模糊与压暗）。
- 全库文件名模糊搜索，并支持书签与最近文件。`Enter` 在当前标签打开，`Ctrl`/`Cmd`+`Enter` 在新标签打开。
- 卡片内容取自单个仪表盘笔记，按可配置的标题级别切分。
- 全部内容类型都能正确渲染，因为渲染走的是 Obsidian 的 `MarkdownRenderer`：纯文本、代码块、```` ```query ```` 块、```` ```base ```` 块，以及装上 dataview 后的 ```` ```dataview ```` / ```` ```dataviewjs ```` 块。
- 卡片内容落在一篇真实笔记里，因此 `![[某表.base]]`、`![[图片.png]]` 与相对链接都按仪表盘笔记所在目录解析。
- 每张卡片的元数据写在 Obsidian 原生注释 `%%card: %%` 里：CSS 片段、跨列数与图标。
- 5 个按内容类型分组的内置 CSS 片段，同时支持引用 `.obsidian/snippets/` 下的自有片段。
- 拖拽排序卡片；卡片正文用普通笔记编辑器修改。
- 移动端与桌面端都能渲染卡片，且只使用公开 API——但卡片操作条是悬停交互，触屏上够不到设置、编辑、删除与拖拽（见已知限制）。
- 在标签页里编辑仪表盘笔记时，首页卡片同步更新。

## 安装

### 社区插件

在 Obsidian 里打开 **设置 → 第三方插件 → 浏览**，搜索 "CardHomeTab" 安装并启用。该方式需要插件已被收录进社区目录。

### 手动安装

1. 从最新 release 下载 `main.js`、`manifest.json`、`styles.css`；或在仓库根目录执行 `npm ci && npm run build`，从 `dist/` 取这三个文件。
2. 在库里创建 `<你的库>/.obsidian/plugins/card-home-tab/`。
3. 把三个文件复制进去。
4. 重载 Obsidian，在 **设置 → 第三方插件** 里启用 "CardHomeTab"。

`dist/` 是自包含的构建产物：每次构建都会清空并重新生成，可以直接安装或发布。

## 仪表盘笔记

默认仪表盘文件为 `Home.md`。标题级别等于**卡片标题级别**（默认 2 级）的标题切出一张卡片，卡片正文延伸到下一个同级或更浅的标题。

```markdown
# 我的首页

## 统计
%%card: css=auto; span=2; icon=lucide-chart%%
- 库内文件：`1204` 个

## 待办
%%card: css=text,user:todo%%
- [ ] 复核发布说明

### 这个三级标题留在卡片内部
## 这里开始另一张卡片
```

- 比卡片标题级别更浅的标题（例如 H1 大标题）始终是页面级的：不会生成卡片，且会终止它上面的那张卡片；YAML frontmatter 同样被忽略。
- 比卡片标题级别更深的标题留在卡片内部正常渲染。
- 标题文字即卡片标题。
- 没有 `%%card:` 行的 section 就是一张纯内容卡片：`span=1`、无片段、无图标。
- 仪表盘就是一篇普通笔记，可以正常打开、编辑、搜索、同步与做版本对比。

### `%%card:` 注释

元数据行必须位于标题之后第一个非空行。

```markdown
%%card: css=base; span=2; icon=lucide-chart%%
```

| 键 | 取值 | 含义 |
| --- | --- | --- |
| `css` | 逗号分隔的片段引用列表，或 `auto` | 只作用于这张卡片的 CSS 片段 |
| `span` | 大于等于 1 的整数 | 卡片跨越的网格列数 |
| `icon` | Obsidian 图标 id，例如 `lucide-chart` | 显示在卡片标题前的图标 |

语法规则：

- 字段间用 `;` 分隔，多值用 `,` 分隔，键值用 `=`。
- 不带来源前缀的引用按内置片段处理：`css=base` 等价于 `css=builtin:base`。
- `auto` 可以与显式引用并存：`css=auto,user:mine`。
- 未识别的键会原样保留。
- `%% %%` 是 Obsidian 原生注释语法：阅读模式下自动隐藏，Live Preview 下以暗色文字显示，这是 Obsidian 的原生行为，而不是插件引入了额外标记。
- 这一行由卡片设置弹窗生成，也完全可以手写。

### `css=auto`

`css=auto` 会套用与卡片正文里实际出现的内容类型相匹配的内置片段：

- 任何围栏代码块都会加上 `builtin:code`；
- 围栏语言为 `base`、`query`、`dataview`、`dataviewjs` 时，加上对应的片段；
- 嵌入 `.base` 文件（`![[某表.base]]`）时加上 `builtin:base`；
- `builtin:text` 始终生效。

自动检测读的是**源码**——围栏代码块的语言标记与 `.base` 嵌入——不做 DOM 探测，因此由其他方式产生的 `.base` 嵌入、或第三方插件从行内语法渲染出来的内容都不会被识别。片段按 text、code、base、query、dataview 的顺序套用。

## 内置片段

内置片段按**渲染出来的内容类型**分组，而不是按视觉风格分：插件只为"卡片里嵌块"这个真正难看的场景兜底，卡片本身的外观交给用户自己的片段。

| 片段 | 目标内容 | 作用 |
| --- | --- | --- |
| `builtin:text` | Markdown 正文 | 首末元素去外边距、标题缩小、列表缩进与表格边框收敛 |
| `builtin:code` | 围栏代码块、行内代码 | 代码块限高 22em 内滚；等宽字体 |
| `builtin:query` | ```` ```query ```` 块 | 查询头部与结果列表紧凑化，限高 24em 内滚 |
| `builtin:base` | ```` ```base ```` 块与 `![[某表.base]]` 嵌入 | 收敛外边距、表头吸顶、限高 24em、toolbar 缩小 |
| `builtin:dataview` | ```` ```dataview ```` / ```` ```dataviewjs ```` | 表格紧凑 + 表头吸顶、列表与任务收紧、错误框缩小 |

`builtin:query` 打的是内部类（`.internal-query-header`、`.search-result-container`）：Obsidian 从不为查询块发出 `.block-language-query` 包装，所以样式必须打在其内部结构上。

## 每卡 CSS 片段如何生效

- 引用格式为 `builtin:名称` 或 `user:文件名`。用户片段从 `<配置目录>/snippets/*.css` 读取——与 Obsidian 自身的 CSS 片段设置是同一个目录。
- **不要**在 **设置 → 外观 → CSS 片段** 里启用卡片片段：在那里启用会让它全局生效。插件自己读取文件内容，完全不碰 `enabledCssSnippets`。
- 片段原文会被整段包进

  ```css
  @scope (.home-card.home-card[data-card-id="…"]) {
    /* 片段原文 */
  }
  ```

  再作为 constructable stylesheet 挂到文档上，因此其中的规则只可能匹配这一张卡片。作用域根类名重复了一次，把优先级抬到 `0,2,0`，避免主题选择器盖过你的片段。
- `:root` 会被改写成 `:scope`。在 `@scope` 内 `:root` 仍指向文档根，永远不会匹配。`.theme-dark .foo` 这类选择器不需要特殊处理：主题类挂在 `body` 上，天然仍然可匹配。
- 片段里不允许使用 `@import`。这样的片段会被拒绝并打日志，卡片就不带它渲染；同一卡片上的其他片段不受影响。
- 样式匹配的是渲染出来的 DOM。作用域内的结构如下：

  ```text
  .home-card[data-card-id]
  ├── .home-card-header        图标、标题、悬停操作条
  └── .home-card-content.markdown-rendered
      └── .home-card-content-inner
          └── 渲染出的 Markdown
  ```

  `markdown-rendered` 加在 `.home-card-content` 自身上，所以能匹配的写法是 `.home-card-content.markdown-rendered p { … }`。

## 使用首页

鼠标悬停在卡片上会显示操作条：

| 操作 | 行为 |
| --- | --- |
| 拖拽手柄 | 在仪表盘笔记里移动该 section |
| 卡片设置 | 弹窗设置图标、CSS 片段（内置 + 用户，多选）与跨列数；写回 `%%card:%%` 行并只重渲染该卡 |
| 编辑 | 打开仪表盘笔记并把光标定位到该卡片的标题行 |
| 删除 | 二次确认后移除该 section |

首页上的卡片是只读渲染的，所有写入都发生在笔记里。

命令：

| 命令 | 含义 |
| --- | --- |
| `打开首页` | 打开首页视图 |
| `刷新所有卡片` | 重新渲染全部卡片 |
| `在标签页打开仪表盘` | 在标签页里打开仪表盘笔记 |
| `新建卡片` | 在仪表盘笔记末尾追加一个卡片 section |

## 设置项

| 分区 | 设置 |
| --- | --- |
| 页面 | 仪表盘文件（带笔记补全的文本输入框，因此可以填一个还不存在的路径）、卡片标题级别（H2–H6）、网格列数（1–6）、替换新标签页、启动时打开首页 |
| 品牌区 | Logo 类型（无 / 内置图标 / 仓库图片 / 网络图片）、图标 id 或图片路径、Logo 缩放（0.2–5）、Logo 颜色（留空跟随主题强调色，仅对内置图标生效）、文字标识文案、显示文字标识、文字标识字号、文字标识字重（100–900） |
| 背景 | 背景类型（无 / 仓库图片 / 网络图片）、亮色背景、暗色背景（留空则暗色模式也用亮色）、背景模糊（0–40）、背景压暗（0–100） |
| 搜索 | 显示搜索框、仅搜索 Markdown、显示路径、显示书签、显示最近文件、结果数（1–50）、最近文件条数（0–20） |
| 片段 | 内置与用户片段及其路径、片段目录、「刷新列表」按钮 |

## 已知限制

1. **只支持一个仪表盘文件。** 没有多套仪表盘页面切换。
2. **卡片正文里不能出现同级标题**——与卡片标题级别同级的标题会被切成另一张卡片。更深级别的标题不受影响。
3. **换行符可能混用。** `updateCardMeta` 与 `appendCard` 一律插入 `\n`，因此编辑一篇 CRLF 换行的仪表盘笔记时，被改动的那一行会变成 `\n`，而文件其余部分仍是 `\r\n`。解析不受影响，只是文件在插件写过的那一行上不再是统一的 CRLF。
4. **设置项不会被 Obsidian 1.13+ 的设置搜索索引。** 设置页是命令式的（`display()`），这是 `minAppVersion` 1.9.0 的要求，且 `getSettingDefinitions()` 返回空数组；1.13+ 会正常显示该页面，但搜不到里面的设置项。
5. **`%%card:` 的值里不能含 `;`**（字段分隔符），没有 `=` 的片段也无法表示。遇到这类无法表示的内容，插件会拒绝改写该行并提示你手工调整，而不是静默丢弃。
6. **CSS 片段不能使用 `@import`。** 这样的片段会被拒绝并打日志，卡片就不带它渲染。
7. **`css=auto` 只从源码检测内容类型**——围栏代码块的语言标记与 `.base` 嵌入——不看渲染出来的 DOM。
8. **需要 Obsidian 1.9.0 及以上。** `@scope` 需要 Chromium 118+，而 `base` 块是 1.9.0 引入的，因此 `minAppVersion` 为 1.9.0。全部功能都只用公开 API，所以移动端也能加载插件并渲染卡片。
9. **`builtin:dataview` 未在装了 dataview 的环境里实测校准。** 它的选择器取自 dataview 官方 styles.css，但代码块实际被包在什么元素里没有在装了 dataview 的库里确认过。如果紧凑化没有生效，需要照真实 DOM 调整这些选择器。
10. **非目标。** 卡片不能折叠、不能嵌套卡片、不能内联编辑，也不能每张卡单独存一个文件——卡片就是仪表盘笔记里的一个 section。`%%card: %%` 这一行在 Live Preview 下是可见的暗色文字。
11. **卡片操作条只靠悬停显示。** 它由卡片上的 `:hover`/`:focus-within` 触发，其中的控件是不可聚焦的 `span`。触屏没有悬停，键盘也没有路径够到它们，因此设置、编辑、删除与拖拽目前只在桌面端可用；卡片本身在移动端正常渲染。
12. **仪表盘文件必须是 Markdown 笔记。** 路径不以 `.md` 结尾时会被拒绝：首页显示为文件缺失，创建时弹出提示，因此不能把插件指到一个 `.canvas` 之类的文件上。
13. **有两个命令会在文件缺失时创建仪表盘文件。** `新建卡片` 与 `在标签页打开仪表盘` 会按设置里当前那个路径直接创建该笔记，不会再问一次；`新建卡片` 随后往里追加一张卡片。路径写错的话，留下的是一个多余的笔记，而不是一次失败。
